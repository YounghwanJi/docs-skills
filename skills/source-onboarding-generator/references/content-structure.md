# 온보딩 문서 내용과 HTML 구조

`study-material-generator`의 학습 구조를 소스 온보딩에 맞게 조정한 내부
가이드다. 다른 스킬의 파일을 읽을 필요가 없다. 출력 형식과 범위는
[SKILL.md](../SKILL.md)의 실행 계약을 따른다.

## 1. 진입점과 읽기 순서

프로젝트 목적, 분석 기준 저장소·커밋·날짜·범위, 시작 경로와 문서 목차를
진입점에 둔다. 작업 트리에 변경이 있으면 커밋만으로 재현되지 않는 부분을
표시한다. 기존 문서 구조를 존중하고 관련 없는 문서를 억지로 만들지 않는다.

학습 목표는 실제 작업으로 확인할 수 있게 쓴다. 로컬 실행·헬스 체크,
핵심 기능의 진입점부터 저장까지 추적, 수정할 파일과 테스트 찾기 등이
해당한다. 목표를 적었다는 이유만으로 실행 검증 완료를 주장하지 않는다.

Markdown은 진입점과 주제별·기능별 문서로 나누고, HTML은 표지와 챕터로
나눈다. 기본 범위는 P0이며 P1~P3는 요청 범위와 프로젝트의 필요에 따른다.

## 2. 핵심 기능의 학습 구조

핵심 기능은 다음 순서로 설명한다.

1. 왜 알아야 하는가: 기능의 목적과 수행할 작업.
2. 개념과 업무 규칙: 도메인 용어, 사전 조건, 권한과 정상·예외 조건.
3. 실제 코드 흐름: 진입점, 핵심 심볼, 데이터 접근과 외부 연동.
4. 변경과 테스트: 수정 위치, 변경 영향, 실행 명령과 검증 상태.
5. 핵심 요약: 본문에서 확인한 사항을 정리하며 새로운 주장을 추가하지 않는다.
6. 문제 상황 Q&A: 권한 실패, 환경 오류, 예외 전파, 데이터 일관성 등
   해당 소스와 테스트에서 확인한 조건을 설명한다.

단순 API·설정 목록에는 이 구조를 반복하지 않는다. 개념은 핵심 작업을
이해할 깊이로 정의·원리·사용 이유를 설명하고 관련 없는 표준 강의를
확장하지 않는다. 설계 의도는 ADR이나 제공 자료로 확인하며 코드만으로
선택 이유를 확정하지 않는다.

## 3. 근거와 검증 상태

- 프로젝트 동작의 근거는 소스·설정·테스트·실행 결과가 우선이다.
- 중요한 설명에는 상대 파일 경로와 심볼·설정 키·테스트명을 연결한다.
- 판단 상태(확인됨 / 추론 / 확인 필요)와 실행 상태(통과 / 실패 /
  미실행 / 해당 없음)를 별도로 기록한다.
- 버전·포트·타임아웃 등은 설정 위치로, 성능 수치는 측정 조건·시점·결과로
  입증한다. 외부 벤치마크를 이 프로젝트의 실측값으로 표현하지 않는다.
- 외부 설명이 필요하면 해당 버전의 공식 문서·표준 등 1차 자료를 사용한다.
- 업무 의미와 비용·운영 제약은 근거가 있을 때 포함하며 비밀 값과
  개인정보는 제거한다. 소스만으로 알 수 없는 운영값은 확인 필요로 남긴다.
- 링크는 확인된 저장소의 커밋 파일 링크 또는 산출물 기준 상대 경로를
  사용한다. 원본 소스 접근 조건을 적고 절대 로컬 경로를 배포하지 않는다.

## 4. 다이어그램과 코드

실제 코드·설정에 있는 노드와 연결만 그린다. 다이어그램 바로 아래에
`그림 설명: ...` 요약을 두고, 노드·화살표·호출·분기에 대응하는 단계별
해설과 근거를 제공한다. 동기·비동기와 정상·실패 흐름을 구별하고 큰
흐름은 나눈다. 정적 분석으로 확정할 수 없는 동적 호출은 추론으로 표시한다.

HTML Mermaid 블록은 다음 형식으로 작성한다.

```html
<div class="diagram-block">
  <pre class="mermaid">flowchart LR
    A["확인한 진입점"] --> B["확인한 처리 컴포넌트"]
  </pre>
  <div class="diagram-alt">그림 설명: 확인한 진입점에서 처리 컴포넌트로 이어지는 호출이다.</div>
</div>
<ol><li>실제 심볼과 근거를 연결해 호출을 설명한다.</li></ol>
```

특수 문자가 들어가는 노드 라벨은 따옴표로 감싸고 Mermaid 화살표는
`-->`, `->>`와 같은 원래 구문을 사용한다. 프로덕션 인프라는 실제 배포
설정·IaC 또는 제공된 운영 자료로 확인되는 범위만 표현한다.

코드와 복사 가능한 명령은 언어·작업 디렉터리·적용 환경·검증 상태와 함께
작성한다. HTML에서는 아래 형식을 사용하되 `<`, `>`, `&` 등 코드의 HTML
특수 문자를 이스케이프한다. JSON 스크립트의 종료 태그는 `\u003c/script>`로
이스케이프해 데이터가 HTML 스크립트를 닫지 않도록 한다.

```html
<div class="code-block" data-lang="text"><pre><code>확인한 명령</code></pre></div>
```

## 5. HTML 데이터와 컴포넌트

[template.html](../assets/template.html)을 출력 위치로 복사하고 예시 데이터
전체를 대상 분석 내용으로 교체한다. CSS/JS는 유지하며 `#content-data`를
편집한다. 데이터 스키마는 템플릿의 주석과 SKILL.md의 필드 매핑을 따른다.

- 문서 필드: `title`, `version`, `createdDate`, `reviewedDate`, `learningGoals`.
  문서 버전과 분석 커밋은 구분하고 실제 검토일만 적는다.
- 기본 탐색: `chapters`의 챕터를 사용한다. 여러 독립 문서 그룹일 때만
  `projects`를 사용한다. 챕터 ID는 전체 문서에서 고유해야 한다.
- 챕터 필드: `id`, `title`, `motivation`, `sections`, `summary`, `qa`.
  제목에 수동 번호를 넣지 않는다. 상세 소제목은 `sections[].heading`과
  본문의 `<h3>`로 구성한다. 좌측은 챕터 탐색, 우측은 내부 TOC다.
- `sections[].html`: 본문, 기능 카탈로그, 설정 표, 근거·검증 상태 표를
  담는다. 새 JSON 필드를 추가하면 자동으로 렌더링된다고 가정하지 않는다.
- `glossary`: `term`, `full`, `definition`, `seeIn`. 도메인 용어와 코드
  명칭을 연결하고 `seeIn`에는 실제 챕터 ID를 넣는다. 첫 약어 사용은
  풀어 쓰고 `<abbr title="...">...</abbr>` 설명을 붙인다.
- `references`: `id`(고유 정수), `text`, `url`, `kind`. 소스·설정·테스트·
  ADR는 `informative`, 실제 규범 문서는 `normative`를 사용한다.
  `text`에는 경로·심볼·판단 상태를 넣고 `url`은 실제 접근 가능한 링크로
  설정한다. `kind: source` 같은 새 분류는 현재 렌더러가 지원하지 않는다.
- 각주: `<sup class="fn" data-ref="1">1</sup>`의 ID와 `references[].id`를
  일치시킨다. 상세한 근거·검증 표는 별도로 본문에 넣는다.
- 일반 기능·설정·API 표는 HTML 또는 GFM 표로 작성한다. `compareTables`는
  ADR의 대안 또는 요청받은 기술 비교에만 사용하고 근거와 판정 문장을 둔다.
- `charts`는 실제 측정값이 있을 때 사용한다. 축·단위·측정 조건·근거를
  표시하고 장식용 수치를 만들어내지 않는다.
- callout은 `note`, `warning`, `deep`를 사용한다. 로그·스크린샷은 실제
  자료만 쓰고 민감정보를 제거한다. 이미지에는 alt 설명을 붙인다.

## 6. 단계별 생성과 검증

큰 문서는 전체 목차·근거 목록을 먼저 만들고 기능·챕터별로 내용을 채운
뒤 용어집·각주·링크를 연결한다. 빈 챕터와 미교체 템플릿 예시는 최종
전달 전에 정리한다. 두 형식을 제공하면 같은 분석 근거와 상태를 유지한다.

[validate-onboarding.py](../scripts/validate-onboarding.py)로 HTML JSON·기본
스키마를 검사한다. 참조 관련 경고도 해결하고 별도로 소스 정확성·링크·
명령·Mermaid 및 UI 동작을 검토한다. 이 검증기는 소스의 실제 동작이나
테스트 통과를 보장하지 않는다.

[bundle-offline.py](../scripts/bundle-offline.py)는 요청 시 Mermaid·D3를
패키지 내 캐시에서 인라인으로 넣고 외부 폰트는 시스템 폰트로 대체한다.
지원 라이브러리를 가져오지 못하면 실패로 종료하며 산출물을 새로 쓰지
않는다. 추가 외부 이미지·스크립트·스타일은 별도로 확인하고 네트워크
차단 상태에서 동작을 점검한다. 소스 링크 접근 조건은 런타임 의존성과
구분한다. 인쇄는 현재 열린 챕터만 포함한다.
