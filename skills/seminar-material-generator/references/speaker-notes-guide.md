# Speaker Notes & Scripting Guide

슬라이드 화면에는 시각적 키워드와 다이어그램만 간결하게 올리고, **자세한 설명과 논증은 발표자 노트(Speaker Notes)에 담는 것**이 학회 및 전문 세미나의 기본 원칙입니다.

---

## 1. 발표자 노트(Notes) 작성 원칙

1. **구어체 스피치 스크립트 (Verbal Script)**:
   - 슬라이드에 적힌 불릿 포인트를 그대로 읽지 않습니다.
   - 청중과 눈을 맞추며 자연스럽게 구술할 수 있는 구어체("이 장표에서 주목해야 할 부분은...", "실제 프로덕션에서 흔히 겪는 함정은 바로...")로 작성합니다.
2. **소요 시간 배분 (Time Allocation)**:
   - 각 슬라이드별 권장 발표 시간(예: `[1분 30초]`)을 노트 첫머리에 명시합니다.
   - 전체 발표 시간(예: 25분)에 맞춰 슬라이드 수와 슬라이드별 시간 가중치를 조절합니다.
3. **핵심 강조 포인트 (Key Emphasis)**:
   - 이 슬라이드를 넘기기 전에 청중의 머릿속에 반드시 남겨야 할 단 하나의 키워드(Takeaway)를 굵은 글씨로 표기합니다.
4. **질의응답 방어 팁 (Q&A Defense)**:
   - 학회나 미팅에서 심사위원/참석자가 공격적으로 파고들 수 있는 기술적 엣지 케이스에 대한 방어 논리를 1~2줄 추가합니다.

---

## 2. 슬라이드 데이터 내 `notes` 작성 예시

```json
{
  "id": "slide-webrtc-bundle",
  "type": "split",
  "heading": "WebRTC BUNDLE과 단일 UDP 포트 다중화",
  "bullets": [
    "과거 미디어 스트림마다 독립 5-튜플(IP:Port) 할당 낭비 해소",
    "RFC 8843 BUNDLE: 오디오/비디오/데이터를 단 1개의 UDP 소켓에 통합",
    "헤더 첫 바이트 기반 제로-오버헤드 커널 디멀티플렉싱"
  ],
  "notes": "[소요 시간: 1분 30초]\n- 구술 스크립트: '여러분, 과거 WebRTC 초기에는 오디오, 비디오, 데이터 채널마다 별도의 포트를 열어야 했습니다. 이는 모바일 환경에서 NAT 포트 고갈과 배터리 소모의 주범이었죠. RFC 8843 BUNDLE 확장은 이 모든 것을 단 하나의 5-튜플 UDP 소켓으로 묶어냅니다.'\n- 강조 포인트: 첫 1바이트 값(0~1 STUN, 20~63 DTLS, 128~191 SRTP)만으로 커널이 패킷을 초고속 분기한다는 점을 짚어주세요.\n- 질의 방어: '포트 하나로 합치면 패킷 지연이 생기지 않는가?'라는 질문이 나오면, 'OS 수준에서 소켓 버퍼 락 경합은 없으며 오히려 conntrack 메모리 오버헤드가 대폭 감소한다'고 답변하십시오."
}
```
